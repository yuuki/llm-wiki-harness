# 追い検索(最初の retrieve が外れたとき)

`retrieve.py` 1 回は最初の一手であり、探索の全部ではない。excerpt に進む前に、候補のタイトルとスニペットから、**問いが尋ねている対象そのもの**を扱うページ(タイトルか冒頭がその概念・システム・主張を名指しするもの)があるかを判定する。あれば excerpt して探索を止める。無ければ(候補が対象に触れる程度、または近傍や survey ばかり)、**最大 2 周**だけ追い検索をして、そこで得たもので excerpt に進む。

1. **名前を当てる。** 正式名称の候補を 1〜3 個(日本語の用語、英語の用語、略語・別名)書き、引く。正確で安い。外れても無駄な結果が返るだけである。
   ```bash
   python3 scripts/wiki-resolve.py "<名前1>" "<名前2>" --type any --top 3
   ```
2. **ページの語彙で問い直す。** ページが使いそうな語(専門用語、英語名、教科書どおりの機序)で 2〜3 個の言い換えを作り、`--also` で 1 回の呼び出しに渡す。retrieve は言い換えごとに全パイプラインを走らせ、元の問いに 2 倍の重みを付けてページを RRF で融合する。言い換えが隣の概念へ逸れても、元の問いのヒットは押し下げられない。各候補には `multi_score` と `matched_queries`(0 が元の問い)が付く。
   ```bash
   python3 scripts/retrieve.py "<元の問い>" --also "<正式名称>" --also "<English term>" --top 5
   ```
3. **最も近いヒットから歩く。** 探しているページが、見つかったページ群を束ねるハブらしいとき(事後分析の source 群に対する実践のページ、メンバーに対する族のページ)に使う。
   ```bash
   python3 scripts/wiki-graph.py neighbors "<最も近いページのパス>" --top 10
   ```
4. **文字列そのもの**(識別子、数値、バージョン、引用句)は `rg -n "<文字列>" wiki/` で引く。

規則:

- 名前と言い換えはエージェント自身が書く。ローカル LLM に問いの書き換えを任せない。重く、名付けもエージェントより弱い。
- 最初の結果を判定してから追う。無条件には追わない。言い換えを等しい重みで融合すると、隣の概念を名指しした書き換えが正しい先頭ヒットを押し下げる。
- `--also` の 1 件ごとにパイプラインを 1 回余分に走らせる。埋め込みが温まっていれば軽いが、初めて埋め込む候補が多いと重い。
- 2 周しても対象を扱うページが見つからなければ、近傍から答えを作らず、ギャップがあると述べる。
