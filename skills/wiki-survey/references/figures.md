# 図表転載の仕様

`wiki-survey` skill の従属資料。フェーズ 5 の図表転載パスを定める。

本文が完成してから独立したパスとして実施する。本文と同時に進めると、章構成が動いたときに図番号が総崩れになる。

---

## 1. 候補の探索

図表は既存の `wiki/sources/_attachments/<slug>/` にあるものだけを使う。新たに PDF から抽出しない。

```bash
# 母集団の source ページが埋め込んでいる図表を洗い出す
rg -o '!\[\[_attachments/[^]|]*' wiki/sources/@YYYY__SOURCE__Title.md

# ディレクトリ側から一覧する
ls wiki/sources/_attachments/<slug>/
```

`<slug>` は `.raw/papers/` の原本名に対応する(例: `arxiv-2605.20119`)。source ページに図が無い文献は転載しない。無いことを理由に別の文献の図で代用してはならない。

---

## 2. 選定基準

判定は一つである。**本文の主張の証拠になるか**。装飾のための図を入れない。

採るもの。

- **構造を示す図**。アーキテクチャ、パイプライン、機構の内部。本文が言葉で説明した構成を一枚で示す。
- **本文が数値で語る現象の根拠グラフ**。本文に「MASE 0.928 対 0.958 の僅差が意思決定では倍近い差になる」と書いたなら、その曲線。
- **対比と矛盾を裏づける図**。2 系統の設計差、否定的結果、分布の違い。

採らないもの。

- 動機づけの例示図(本文の論証を支えない)。
- 合成クロップや、複数図の切り貼りで作られた画像(元の図表番号に対応しない)。
- 定性的な概念図で、本文の主張と対応しないもの。

配分。**総量の上限は設けない**。基準は選定基準だけであり、証拠になる図が多い章には多く入る。

既存の長編ページの実測では、H2 見出し 1 本あたりの点数が 0.3 点から 10.7 点まで分布している。`KVキャッシュ管理の教科書` は H2 が 14 本(13 部と付録 1 本)で埋め込み 150 点、`NIC光トランシーバーのモニタリング` は H2 が 13 本で 4 点(すべて自作図)、`AIワークロード基盤技術サーベイ` は 817 行で 0 点である。密度から品質は決まらない。図が無い長編は成立する。

守るのは配置の規則だけである。

- **総括章、未解決の問い、付録は 0 点**。既出の観察を判断へ並べ直す章に単一ソースの図を貼ると、その節が特定 1 論文の議論に見える。
- 章をまたいで同じ図を 2 度貼らない。最初に現れる章に残し、後の章は参照へ置き換え、図番号の欠番を詰める。
- 1 つの章の図が特定 1 論文に偏ったら、その章の論証が単一ソースに依存している疑いがある。図ではなく本文を見直す。

## 3. 挿入前の実見

**候補画像は必ず Read して中身を確認する**。ファイル名と中身が一致しない例が実際に見つかっている。

- ある論文の `table2-table.png` は Table 2 ではなく Figure 2 下部の切り出しだった(不採用に差し替え)。
- ある論文の Figure 1 は構成図ではなく動機づけの例だった(Figure 2 に差し替え)。

実見で確認するのは 3 点である。

1. 図の内容が、貼ろうとしている位置の主張と対応しているか。
2. 原本の図表番号がファイル名の想定と一致しているか。
3. 切り出しの範囲が不完全でないか(軸ラベルや凡例が欠けていないか)。

---

## 4. 書式

### 転載図(source ページ由来)

```markdown
![[_attachments/<slug>/<file>.png]]

**図N-M**:何が描かれているか(1〜2 文)。そして本文のどの主張、どの数値に対応するか(1 文)。
(Source: [[@YYYY__SOURCE__Title]], 図 N)
```

- 図番号 `図N-M` は「章番号 - 章内の出現順」。表は `表N-M`。
- キャプションの後半で**本文との対応を必ず書く**。「〜という本文の指摘はこの並びに対応する」「〜という数値はこの一致度である」のように、読者が本文へ戻れるようにする。図の説明だけで終わらせない。
- 出典行には**原本の図表番号**を付ける。
  - 論文: `図 N`、`表 N`。部分図は `図 3(a)`、複数図の統合は `図 1–3`。
  - スライド: `p.N`。
  - 映像: `frame-NNN`。
- 本文の主張の**直後**に置く。節の末尾にまとめない。

### 自作図(文献横断調査型)

対象そのものの構造を説明する図は自作してよい。保存先と書式が転載図と異なる。

```markdown
![[Attachments/<ページ名>/figure-NN-<slug>.png|900]]

図 N <何が描かれているか>。<設計上の含意>。
```

- 保存先は `Attachments/<ページ名>/`(vault ルート直下の `Attachments/`、`wiki/sources/_attachments/` ではない)。
- ファイル名は `figure-NN-<英小文字ハイフン>.png`。
- 幅は `|900` を指定する。
- キャプションは太字番号を使わず「図 N 」で始める(転載図と書式を分け、自作か転載かが見て分かるようにする)。
- **自作は概念図に限る**。数値グラフを自作しない。数値は原典の図を転載するか、表で示す。

## 5. 検査

挿入した全件を確認する。`SKILL.md` のフェーズ 5 で release する前、またはフェーズ 6 の検証の一部として実行する。

```bash
# 埋め込みパスを抽出して実ファイルの存在を確認する
rg -o '!\[\[[^]|]*' "wiki/surveys/<タイトル>.md" | sed 's/^!\[\[//' | while read -r p; do
  case "$p" in
    _attachments/*) f="wiki/sources/$p" ;;
    *) f="$p" ;;
  esac
  [ -f "$f" ] || echo "MISSING: $p"
done
```

欠損 0 件が保存の条件である。あわせて次を確認する。

- 図番号が章内で連番になっているか(欠番と重複が無いか)。
- 全キャプションに本文との対応が書かれているか。
- 全出典行に原本の図表番号が付いているか。

---

## 6. 著作権への配慮

書籍ソースは `publish: false` を持つ(`wiki/meta/conventions.md` §9)。書籍由来の図を転載するかは**ユーザーの判断を仰ぐ**。

- 転載する場合も、source 側と question 側の `publish` 設定は変更しない。
- 転載しない判断になったら、図の代わりに本文の記述と参照リンクで済ませる。

---

## 7. ログ

図表転載は本文執筆とは別のコミットとログエントリにする。

```markdown
## [YYYY-MM-DD] wiki-survey | <タイトル>(図表転載)
- 更新: [[<タイトル>]]
- 各 source ページの `_attachments/` から N 点を抜き出し、本文の該当主張の直後へ挿入した(図X-Y〜図Z-W)。
- 選定基準は「本文の主張の証拠になるか」。<主要な図を 3〜5 点、選んだ理由つきで列挙>
- 実見の結果差し替えたもの: <ファイル名と理由>
- 0 点とした章: <章名と理由>
- 全 N 点の画像パスは実ファイル存在を検査済み。address は再採番していない。
```
