# 増補 subagent の要点

`wiki-survey` skill の従属資料。[`SKILL.md`](../SKILL.md) の「一括増補」で、1 ページを担当する subagent へ**このファイルだけ**を読ませる。SKILL.md 本体と参照文書を毎回全部読ませると、それだけで 1 体あたり数万トークンを使う。

ここに書くのは要点である。規則の本文は正本にある。判断に迷ったときだけ、該当する正本の節を読む。

| 項目 | 正本 |
|---|---|
| 増補の手順 | [`SKILL.md`](../SKILL.md) の「既存ページの増補」 |
| 執筆時の判断(出典、数値、所属) | [`SKILL.md`](../SKILL.md) の「フェーズ 4」 |
| 検査の FAIL と WARN | [`SKILL.md`](../SKILL.md) の「フェーズ 6」、`python3 scripts/wiki-survey-check.py --help` |
| 図表 | [`figures.md`](figures.md) |
| 用語(原語、カタカナ、漢語) | [`wiki/meta/japanese-style.md`](../../../../wiki/meta/japanese-style.md) |
| 文章規範 | `japanese-tech-writing` skill(`.claude/skills/japanese-tech-writing/SKILL.md`) |

---

## 1. 入力

メイン文脈から次を受け取る。受け取っていないものを自分で探しに行かない。

- 担当ページのパス 1 本。
- 候補 source の一覧(`scripts/survey-augment-plan.py` の出力。関連度つき)。候補は機械的な推定であり、全部を織り込む義務は無い。座標系に置けないものは理由を書いて見送る。
- 共有 source の主張カード(`.vault-meta/survey-augment/cards/<source>.md`)。カードにある source は**カードを素材にする**。カードに無い数値や記述が必要なときだけ、source ページの該当節を `rg -n` で位置特定して読む。全文を読み直さない。
- カードの無い source は、source ページを読む。800 行を超えるなら `python3 scripts/wiki-excerpt.py <path> --tail 15 --budget-tokens 1800` で概要を取ってから必要な節を読む。

`retrieve.py` で候補を探し直さない。候補の探索はメイン文脈が済ませている。

## 2. 手順

1. **章立てだけを読む**。担当ページの全文を読まない。`python3 scripts/wiki-excerpt.py "<ページ>" --tail 15 --budget-tokens 1800` と `rg -n '^## |^### ' "<ページ>"` で、座標系の章、横断的発見の章、未解決の問いの位置を取り、その節だけを読む。
2. **座標系へ置く**。各 source が既存の軸のどの値に入るかを決める。どこにも入らなければ軸か値を 1 つ足し、座標系の表も直す。軸を 2 本以上足す、章の半分に触れる規模になったら、増補をやめてメイン文脈へ「改稿が必要」と返す。
3. **該当する章すべてへ織り込む**。末尾に「追記」節を足して済ませない。手法の表、横断的発見(補強なら既存の発見へ、新しい観察なら発見 N+1)、未解決の問い(閉じた問いは落とし、開いた問いを足す)に置く。
4. **frontmatter**。`sources` に織り込んだ source を足し、`updated` を今日にする。`address` と `question` は変えない。
5. **保存**。`bash scripts/wiki-lock.sh acquire "<ページ>" --stale-after-sec 1800` を取ってから Edit し、`release` する。担当ページ以外のファイルを編集しない。
6. **検査**。`python3 scripts/wiki-survey-check.py check "<ページ>"` で FAIL を 0 にする。WARN は 1 件ずつ判断し、残すものは理由を報告に書く。追加した数値を数件、source ページへ `rg` で遡及する。
7. **図表**。§4 の条件を満たすときだけ行う。
8. **報告を書く**(§5)。log、index、hot は触らない。メイン文脈が報告から書く。

## 3. 執筆の要点

出典と数値。

- source ページに書かれていない数値と主張を書かない。wiki に無いことは「wiki のソースからは確認できない」と書き、未解決の問いへ送る。
- 数値には評価条件(データセット、比較対象、規模、版)を付ける。条件の違う数値を同じ表に並べない。
- 個人の著者名を主語にするときは初出で所属を括弧書きする。所属は source ページか entity ページから取り、見つからなければ書かない。
- 同じ単一出典が続く間は空行で段落を割らず、段落末に `(Source: [[...]])` を 1 回だけ付ける。論点が変わるときだけ段落を割る。

文体(機械検査で FAIL になるもの)。

- 一文一行、常体。
- em ダッシュと 2 倍ダッシュを使わない。漢字語の並列の中黒は読点にする。wikilink の中は触らない。
- 「重要なのは」「正面から」「多角的」「掘り下げ」を使わない。

文体(検査に載らないもの。書いた後に自分で見る)。

- 和文に英単語を素のまま混ぜない。略語と固有名詞とコードは原語、一般語はカタカナ、定着した漢語(障害、検知、緩和、箇所特定)は漢語。初出の専門用語は「和訳(原語)」。
- 予告と総括の空句、空虚な形容(不可欠、核心的、包括的)、空虚な動詞(深掘り、言語化)を書かない。
- 翻訳調の比喩(運ぶ、開かれた問い、効く)と無生物主語の擬人化を書かない。主体と対象を具体語で言い直す。
- 推量や可能性の表現を根拠なく断定に変えない。異なるものを「同じ」とまとめない。因果には機構を一文添える。
- 見出しを結論のセリフにしない。対象を指す名詞句か問いにする。
- 同じ主張を言い換えて繰り返さない。隣の章と同じことを書いていたら片方に寄せる。

## 4. 図表

新 source に、本文で書いた主張の証拠になる図があるときだけ入れる。

- 使えるのは `wiki/sources/_attachments/<slug>/` にある既存の図だけである。source ページの `![[_attachments/...]]` を `rg -o` で洗い出す。
- **挿入する前に画像を Read して実見する**。ファイル名と中身が食い違う例がある。確かめるのは、主張との対応、原本の図表番号、切り出しの欠け。
- 画像の Read が失敗またはタイムアウトしたら、図表は入れずに候補パスを報告に書いて終える。再試行を繰り返さない(メイン文脈が別パスでまとめて処理する)。
- 総括章、座標系の章、未解決の問いには貼らない。同じ図を 2 度貼らない。章内の図番号を詰め直す。
- 書式は figures.md §4。キャプションの後半に本文との対応を書き、出典行に原本の図表番号を付ける。

## 5. 報告

`.vault-meta/survey-augment/reports/<ページの basename>.md` に書き、同じ内容を最終メッセージで返す。報告は形式を固定する(メイン文脈が log へ転記し、欠けを数えて検査する)。

```markdown
# <ページの basename>
- status: done | skipped | needs-rewrite | failed
- 追加 source: [[...]], [[...]]
- 見送った候補: [[...]](理由)
- 触れた章: <章名を列挙>
- 座標系への配置: <source → 軸の値。新設した軸や値>
- 横断的発見と未解決の問い: <補強した発見、新しい発見、閉じた問い、開いた問い>
- 図表: <挿入した図番号と出典 / 実見して不採用にしたもの / 画像 Read 失敗で保留した候補パス>
- 検証: wiki-survey-check の FAIL 件数、残した WARN と理由、数値の遡及件数と結果
```
