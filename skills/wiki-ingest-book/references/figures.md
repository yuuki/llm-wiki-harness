# 書籍図表の抽出手順

`wiki-ingest-book` の従属資料。SKILL の Step 0.5 から移した長いクロップ手順・スキャン PDF 警告・フォント判別である。方針の箇条書きは SKILL 側が正本である。

## 役割

**クロップと章テキストからのキャプション抽出は読み手(またはオーケストレータの Step 0.5)の仕事である。** 書き手は briefing の図表表とコンタクトシートと extract の「図表」節だけを使う。章 txt を全文 Read しない。このファイルのクロップ手順(§1.7・§4)はオーケストレータと、規則が立たないときにクロップを任された読み手だけが使う。書き手に章本文を読ませてクロップさせない。1〜2 章の一体モードだけが、読了とクロップを 1 体で行う。

図表の取り扱いは `wiki-ingest-paper` の Step 0.5(コンタクトシート確認 → 取り込み対象の確定 → attachment 配置 → 本文近傍への埋め込み)と同じ扱いとする。選定方針も共通で、いずれも「本文が参照している図表は除外理由がない限り全部取り込む」。書籍固有の違いは「一括抽出の規模制御」と「章単位でのスコープ限定」だけである。

> [!important] 全ページレンダリング(`pdftoppm` 全頁)は禁止
> スライドと違い、書籍は数百ページある。ページ画像化はしない。埋め込み画像抽出とページ範囲限定のクロップだけを使う。

---

## 1. 一括抽出の規模制御

**ページ数は実行前に判定する。実行してみてから判断しない。** `fetch-book.sh` の出力にある `pages=` の値を見て、**300 ページ超なら `extract-paper-images.mjs` を一切実行せずクロップのみ方針に進む**。全ページを pdf.js でレンダリング+走査するこのスクリプトは 400 ページ級の書籍では Bash ツールの既定タイムアウト(180秒)を超えて中断しやすく、中断すると一時ディレクトリ(`.images.tmp-*`)が残ってクリーンアップの手間が生じる。「まず実行して枚数を見てから 300 ページ超なら諭す」という運用は禁止(実行自体を避ける)。

300 ページ以下の場合のみ、**一括抽出をオーケストレータが 1 回だけ**行う:

```bash
node scripts/extract-paper-images.mjs ".raw/books/<slug>/<slug>.pdf" ".raw/books/<slug>/images"
```

抽出画像が 100 枚超になった場合は結果を破棄しクロップのみ方針に切り替える(装飾画像が大量に出るため)。

もし誤って実行してタイムアウト等で中断した場合、残った一時ディレクトリは `rm -rf` ではなく `find "<dir>" -maxdepth 1 -type d -name '.images.tmp-*' -exec rm -r {} +` のように対象を限定して削除する(サンドボックス環境では素の `rm -rf <path>` がパターンマッチで拒否されることがある)。

抽出を実行した場合は、`wiki-ingest-paper` Step 0 と同じクリーンアップを行う。`.raw/books/<slug>/images/` に保持するのは**埋め込み画像(`image-*.png`)と `images.json` だけ**とし、`page-*.png` のページ単位レンダリング画像は PDF 原本から再生成できるため削除する。手で `find` / `python -c` しない。

```bash
python3 scripts/wiki-verify-ingest.py --cleanup-images ".raw/books/<slug>/images"
```

一括抽出をスキップした場合は `page-render` 類は残さず `images/` を空にしてよい(この場合クリーンアップ手順は不要)。

## 1.5 本文の図参照を grep して総点数を把握する

「300 ページ超だから一括抽出しない」と決めた後、図の探し方を各章 subagent に丸投げすると、章ごとに手探りのクロップが走って高くつく。分割済みの章テキスト全体を 1 回 grep すれば、書籍全体で図が何点あるかが数秒で分かる:

```bash
grep -ohE "図\s?[0-9A-Z]+\s?-\s?[0-9]+" .raw/books/<slug>/chapters/*.txt | sort -u   # 和書
grep -ohE "(Figure|Table)\s[0-9A-Z]+[-.][0-9]+" .raw/books/<slug>/chapters/*.txt | sort -u  # 洋書
```

結果で方針を分岐する。**判断基準は点数そのものではなく「書籍全体に通用する機械的な切り出し規則が立つか」である**:

- **規則が立つ(既定・推奨)**: **点数が何点でもオーケストレータが 1 パスで全図を切り出す**。§1.7 の手順でキャプションの判別条件と画像矩形の対応が全ページ安定して取れるなら、100 点超でも数分で終わる。実例として 392 ページ・図 124 点の書籍を、キャプションのフォント判別 + `get_image_rects()` の 1 スクリプトで全点切り出せた(自動 122 点 + 手動 2 点)。subagent には**完成したファイル名・原本ページ・キャプション原文の表**を章ごとに渡し、「この記述の直後に埋め込め」という指示だけにする。
- **規則が立たない**(章ごとに図の作られ方が違う、ラスタ図とベクター図が混在して一律に扱えない): 規則が立たないクロップはオーケストレータか読み手が行う。書き手に章本文を読ませてクロップさせない。判明している判別条件は**読み手用** briefing に書いて共有する(各章が別々に試行錯誤するのを防ぐ)。
- **総点数が概ね 10 点以下**: 規則の有無によらずオーケストレータが片付ける。少数のときに subagent へ委任すると、ツール起動のオーバーヘッドと座標の当て損ねの割に得るものがない(過去、図表点数が多い章で subagent への委任が繰り返し打ち切られ、結局オーケストレータが直接処理した事例がある)。
- **grep が 0 件**: 図がほぼ無い書籍(論説・インタビュー中心の本など)。`images/` を作らず図の工程ごと省略し、その旨を log の備考に書く。

図の作業が無い章には「**この章に図はない。図の作業は不要**」と明記する(書かないと subagent が探しに行く)。

## 1.7 埋め込み画像があるなら `get_image_rects()` を優先する

PDF に画像オブジェクトが埋まっていれば、キャプション位置から図の領域を推定する必要はなく、画像そのものの矩形が取れる。こちらの方が枠のずれ・隣接図の混入が起きない。

> [!warning] スキャン PDF では `get_image_rects()` が使えない。**矩形がページ全面かを最初に確かめる**
> ページ全体をスキャン画像として持ち、その上に OCR テキスト層を重ねた PDF がある(古い書籍の電子化版に多い)。この構成では `get_images()` が返す「埋め込み画像」は**図ではなくページのスキャンそのもの**で、矩形は必ずページ全面になる。気づかずに本節の本流を走らせると、全ページが 1 枚の巨大な図として切り出される。
>
> 判定は 1 回で済む。図のあるページの矩形をページ矩形と比べ、**ほぼ一致していたらスキャン PDF である**:
> ```python
> rects = [r for im in page.get_images(full=True) for r in page.get_image_rects(im[0])]
> print(page.rect, [tuple(round(v) for v in r) for r in rects])
> # 例: Rect(0,0,415.9,647.3) に対し [(0,0,416,647)] → ページ全面。スキャン PDF
> ```
> この場合は `get_image_rects()` を捨て、**キャプション座標クロップ(§4)を全図に適用する**。スキャン PDF は組版が単純(図が上、キャプションが下)なことが多く、「ランニングヘッダの下端からキャプション末尾まで」を切るだけで足りる。**クロップ後は 1 点ずつ Read で開き、図の上端・キャプション下端が切れていないか確認して境界を詰める**(実例 *The Sciences of the Artificial*: 7 点中 6 点で上端または下端が切れており、`y0` を 78 → 55〜66、`y1` を +10〜60 して再クロップした)。
>
> **OCR はキャプション行そのものを落とすことがある**。同書の Figure 4 は「Figure 4」の行だけがテキスト層から欠落し、キャプション本文(`Chess position used in memory experiment`)しか残っていなかった。§1.5 の grep で得た図番号の集合と突き合わせれば欠番として必ず現れるので、**本文中の参照(`the board of figure 4` 等)を grep して所在ページを特定する**。点数照合を省くとこの図は永久に埋め込まれない。

> [!tip] 洋書はキャプション記法だけで分離できることが多い。**フォント調査より先にこれを試す**
> 洋書のキャプションは `Figure 4.1: Deep and shallow modules. ...` と**コロンを伴う**のに対し、本文中の参照は `as shown in Figure 4.1` とコロンを伴わないのが通例である。したがって
> ```python
> m = re.match(r"(Figure|Table)\s+\d+\.\d+:", txt)
> ```
> で始まるテキストブロックだけを拾えば、フォント判別なしでキャプションだけが正確に取れる。実例(*A Philosophy of Software Design*、188 ページ)ではこの 1 行で図 14 点のキャプションが過不足なく取れ、フォント調査は不要だった。
>
> **図のあるページ 1 枚の `get_text()` を見てコロンの有無を確かめる**。分離できるなら次のフォント判別は飛ばしてよい。分離できない書籍(和書全般、コロンを使わない洋書)だけが次の手順の対象である。

> [!warning] 「図N-M」で始まる行をキャプションとみなしてはならない
> 和書の本文には「図9-1は、システムが正常に機能している状態を示しています。」のような**本文中の図参照**が頻出し、これも `図N-M` で始まる。素朴に `text.startswith("図")` で拾うと参照行がキャプションとして数えられ、**直上の画像スロットを奪って本物のキャプションが未マッチになる**(実測: 124 点中 65 点が取りこぼし)。和書はコロンを使わないのでこの判別が要る。
>
> **キャプションは本文と別フォント・別サイズで組まれているので、そこで判別する。** まず図のあるページを 1 枚調べて条件を確定させる:
> ```bash
> uv run --with pymupdf --cache-dir "$TMPDIR/uv-cache" python3 - <<'PY'
> import fitz
> doc = fitz.open(".raw/books/<slug>/<slug>.pdf")
> page = doc[<図のあるページ>-1]
> for blk in page.get_text("dict")["blocks"]:
>     if blk.get("type") != 0: continue
>     spans = [s for l in blk["lines"] for s in l["spans"]]
>     txt = " ".join(s["text"] for s in spans).strip()
>     if not (txt[:6].count("図") or txt[:8].startswith(("Figure", "Table"))): continue
>     print(sorted({round(s["size"], 1) for s in spans}),
>           sorted({s["font"] for s in spans}), "::", " ".join(txt.split())[:50])
> PY
> ```
> 実例(オライリー・ジャパンの和書): キャプションは `GothicBBBPr6N-Medium` 7.1pt、本文参照は本文明朝 `RyuminPr6N-Reg` 8.5pt を含む。判定式は「**本文フォントを 1 つも含まず、最大サイズが本文より小さい**」が頑健である。キャプションフォントとの完全一致で絞ると、キャプション中に等幅や太字が混じる図(「図4-5 + ∞ を仮想キーとして使用する場合」等)を取りこぼす — 実際これで 5 点落とした。洋書は本文セリフ体に対しキャプションがサンセリフ体・イタリック、といった差になることが多い。**書籍ごとに 1 回調べれば全ページで通用する。**

条件が決まったら章のページ範囲を走査し、「キャプション」と「その直上の未使用画像矩形」を対応づけて `page.get_pixmap(clip=r, dpi=200)` で保存する。同一ページに複数の図が載るので、**1 つの画像は 1 つのキャプションにしか割り当てない**(使用済みを記録する)。**ベクター図で `get_images()` が空を返すページだけ**、次の §4 のキャプション座標クロップにフォールバックする。

**キャプションが図の次ページに送られることがある**。ページ末に図が入り、キャプションだけが改ページされる組版があるためで、同一ページに未使用の画像矩形が無い場合は**前ページの末尾の未使用矩形にフォールバックする**。実例(*A Philosophy of Software Design*)では 1 ページに 2 図が載り、2 つ目のキャプションだけが次ページにあった。このフォールバックを入れると点数照合は通ってしまうので、**割り当て後に必ず画像を Read で開いてキャプションと中身が一致するか確認する**(図が前後で入れ替わっていても点数照合では気づけない)。

切り出し後は**必ず点数を照合する**。§1.5 の grep で得た図番号の集合と、切り出せた図番号の集合を突き合わせ、**差分をゼロにしてから fan-out に進む**(残った数点はページを直接見て手動クロップする)。未マッチを放置すると、その章の subagent は「表にない図」の存在に気づけないまま本文だけ書く。切り出した画像は**代表数点を Read ツールで開いて枠のずれを目視確認する**(ベクター図フォールバック分は特に)。

## 2. コンタクトシートで確認してから選定する

`wiki-ingest-paper` Step 0.5 §1 と同じ規律。斜め見しない。`python3 scripts/contact-sheet.py --manifest ".raw/books/<slug>/images/images.json" --out "$TMPDIR/cs-<slug>" --index-txt` でシートを作り、シートを Read する。セルが読めない・番号が確定しないものだけ個別に Read。本文参照分は全件必須という規律は変えない。シートが 3 枚を超えるなら本文必須番号に対応する画像だけを `--glob` で渡す。シートを Read しすぎない。

キャプション抽出(`Figure N.M` / `Table N.M` を章 txt から拾う)はオーケストレータまたは読み手の仕事である。書き手は briefing の図表表とコンタクトシートと extract の「図表」節だけを使い、章 txt を全文 Read しない。書き手が見るのは自章のページ範囲に該当するシートと表だけ。

```bash
# 読み手またはオーケストレータ。書き手は走らせない
grep -n "^Figure \|^Table " ".raw/books/<slug>/chapters/ch-NN.txt" | head -40
```

## 3. 選定(除外リスト以外は全部)

書籍(特に実務解説書)は 1 章に 10〜20 点の図表を持つことが普通で、そのほとんどは計測結果・比較グラフ・構成図として本文の主張を直接裏づける。優先度による足切りはせず、**除外リストに当たるものだけを除く**方式で選ぶ(`wiki-ingest-paper` Step 0.5 §2 と同じ方式):

**除外する**(これ以外は基本的に含める):

- ページ全体のスクリーンショット相当の画像(UIキャプチャ・コード全文の画像化等、本文中のコードブロックで代替可能なもの)
- 凡例のみの画像、装飾目的の画像、著者近影等の写真
- 同一実験の**ほぼ同一構図の繰り返し**(例: 同じグラフの試行回数だけ異なるバリエーションが 5 点以上続く場合、代表 1〜2 点+それ以外は本文中で言及のみに留める。何点を省略したかは subagent 報告に明記する)
- 本文の言及なしに意味が取れない断片図(キャプション座標クロップで文脈を含められないもの)

1 章あたりの枚数に上限は設けない。図表点数が多い章(20 点超)では、読み手またはオーケストレータがクロップを本文読解と並行して機械的に進めてよい(逐一の重要度判定に時間をかけすぎない)。書き手の埋め込みは、既に揃った図表表とコンタクトシートと extract の「図表」節から行う。書き手に章本文を読ませてクロップさせない。

## 4. ベクター図のキャプション座標クロップ(オーケストレータまたは読み手)

埋め込み画像が取れない場合は `wiki-ingest-paper` の「Step 0.5 §1.5 PyMuPDF キャプション座標クロップ」の定型を、対象章のページ範囲に限定して適用する(`uv run --with pymupdf --cache-dir "$TMPDIR/uv-cache" python3 - <<'PY'` 起動、キャプション座標から `get_pixmap(clip=...)` でクロップ)。詳細手順は [`../../wiki-ingest-paper/references/figures.md`](../../wiki-ingest-paper/references/figures.md) を開く。書き手は本節を使わない。

## 5. attachment の配置

書籍 1 冊 = 1 ディレクトリに集約する。

```bash
mkdir -p "wiki/sources/_attachments/<slug>"
cp ".raw/books/<slug>/images/image-042-001.png" \
   "wiki/sources/_attachments/<slug>/ch03-fig3.2-bathtub-curve.png"
```

ファイル名は `ch<NN>-fig<N.M>-<内容>.png`。**`token`・`secret`・`password`・`credential`・`key` を含む名前は禁止**(サンドボックスの Read 拒否ルールに引っかかる。`wiki-ingest-paper` Step 0.5 §3 参照)。

## 6. 埋め込みは本文近傍

`wiki-ingest-paper` Step 0.5 §4 と同じく「## 図表」のような図表専用セクションは作らない。各図はそれが言及されている記述の直後(例: 「主要概念」「主要主張」節内の該当箇所)に埋め込む。

```markdown
![[_attachments/<slug>/ch03-fig3.2-bathtub-curve.png]]
(Figure 3.2. キャプションの日本語要約 1〜2 文。ch.3)
```

画像は付随する画像自体が `publish: false` ページからのみ参照されるため、Publish の「リンクされたファイルのみ公開」運用では外部公開されない。
