# 章抽出ファイルのスキーマ

`wiki-ingest-book` / `wiki-ingest-thesis` の従属資料。3 章以上の ingest で、読み手(extract)が書くファイルの形である。書き手(write)はこのファイルと briefing だけで章 source を組む。章本文の全文は書き手の常駐文脈に載せない。

このファイルはスクラッチ専用である。**wiki に置かない。git 管理しない。extract を `.raw` に置かない**(`.raw/books/<slug>/` にも `.raw/theses/` にも置かない。原本は不変)。

置き場は briefing と同じスクラッチ:

```
<scratch>/extracts/ch-NN.md
```

例: `/tmp/book-<slug>/extracts/ch-03.md`、`/tmp/thesis-<slug>/extracts/ch-03.md`、またはユーザー作業ディレクトリ配下。

必須見出しは次のとおり。欠落は `scripts/wiki-extract-check.py` が見つける。見出し文言は一字一句この形にする。

```
# extract ch-NN <章題>
## 一行要約
## 主要主張
## 実践的指針
## 登場 entity
## 登場 concept
## 図表
## 引用(locator 付き)
## 未解決の問い(章が投げたままのもの)
## 書き手への注意
```

該当が無い節も見出しは残す。**見出しは空でも残す(schema)。** 本文は「該当なし」の 1 行でよい。引用節がファイルの 40% を超えたら `QUOTE-HEAVY` で検査が落ち、書き手は起動されない。

## 共通規則

- 各箇条書きは短くする(1 行、長くて 2 行)。
- 主張・指針・entity・concept・図表・引用・問いには **locator** を付ける。印字ページ `(p.42)` を優先する。印字ノンブルが取れないときだけ章テキストの行番号 `(ch-03.txt:128)`。
- **本文の逐語コピーは `## 引用(locator 付き)` だけ。** ほかの節は言い換えとラベルに限る。
- 引用は必要最小(章の核になる文だけ。引用節がファイルの 40% を超えたら厚すぎる)。
- 出典に無いことは書かない。訓練データの知識で補完しない。
- 日本語・常体。用語は `wiki/meta/japanese-style.md` に従う。
- 書き手が source ページの要約・主要概念・主要主張・実践的指針・関連・埋め込み位置を、このファイルと briefing だけで組み立てられること。

## 各節の中身

### `# extract ch-NN <章題>`

`ch-NN` は 2 桁。章題は briefing で確定した原題。勝手に整形しない。

### `## 一行要約`

章全体を 1 文(長くて 2 文)。book / ハブ entity の「構成と主要テーマ」にそのまま載る文にする。

### `## 主要主張`

章が主張していること。3〜7 件。各行に locator。書き手の `key_claims` と `## 主要主張` の種にする。

### `## 実践的指針`

実務書・運用章だけ厚くする。研究章・理論章は「該当なし」でよい。各行に locator。

### `## 登場 entity`

書き手が resolve する人名、組織、製品、データセット。1 行 1 件: `名前 — 章内の役割 (locator)`。共著者・一度きりも列挙する(書き手が stub 判定する)。サーベイの引用文献は列挙しない(thesis briefing の規律)。

### `## 登場 concept`

章の核になる手法・枠組み・問題ドメイン。1 行 1 件: `用語(原語) — 章内の位置づけ (locator)`。単一章で閉じる用語も、書き手が source の「主要概念」に載せるために残す。

### `## 図表`

本文が参照する図・表。1 行 1 点: `図N.M — キャプションの要旨 (locator)`。briefing の図表表にあるならその旨を添える。除外すべきもの(装飾・著者近影等)は「除外:」と理由。点数が 0 なら「該当なし」。書き手は briefing の表とコンタクトシートで埋め込む。

### `## 引用(locator 付き)`

逐語が必要な文だけ。各引用は短く、locator 必須。書き手が主張の根拠にする。ここに本文を再掲しすぎない。

### `## 未解決の問い(章が投げたままのもの)`

章が明示した open problem・次の宿題。読み手が作った問いではない。書き手が concept の `## 未解決の問い` へ還流する種にする。

### `## 書き手への注意`

OCR で読めない箇所、次章・次部の扉混入、書かないこと、対応する出版論文との食い違い、テンプレ型(研究章 / サーベイ章 / 導入)の指定など。wiki には書かない作業メモ。

## 最小例

```markdown
# extract ch-03 信頼性数学

## 一行要約

故障率と修理率から可用性と MTTF を導く章であり、直列・並列の構造関数を実務の計算手順に落とす。

## 主要主張

- 直列系の信頼性は各要素の積であり、要素数の増加で急落する (p.44)
- 予防保全の間隔はバスタブ曲線の摩耗期に合わせないと逆効果になる (p.61)

## 実践的指針

- 現場の MTTF は打切り標本を打ち切りのまま扱え、単純平均するな (p.52)

## 登場 entity

- Weibull — 摩耗故障の分布として導入される (p.48)

## 登場 concept

- 可用性(availability) — 修理を含む長期稼働割合。信頼性とは別量 (p.41)

## 図表

- 図3.2 — バスタブ曲線の 3 期 (p.47)。briefing 表にあり

## 引用(locator 付き)

- "Reliability is the probability that a system will perform its intended function" (p.40)

## 未解決の問い(章が投げたままのもの)

- 従属故障を独立近似したときの誤差をどう見積もるかは章内で閉じない (p.70)

## 書き手への注意

- 章末に第 4 章の扉が混入している。第 4 章の内容は書かない
- 実務書なので実践的指針を厚くする
```
